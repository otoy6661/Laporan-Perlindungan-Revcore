# RevCore — Ten-Gate Security Audit Matrix

Build date: 15 November 2026 (`151126`)
Package: `com.revcore.android`
Scope: JOB 2 — complete ten-gate integrity implementation.

## 1. Design summary

The ten gates are **not ten independent keys**. They share one trust anchor: the
official APK signing certificate (`SHA-256 c649cb4f…18d098`). No tenth operational
key was generated and no key from `RevCore_Keys.txt` was reused for a new purpose.

Trust chain:

```
BuildConfig.EXPECTED_SIGNER_SHA256 (public pin)
  → installed APK signer certificate (PackageManager)
  → detached policy signature (SHA256withRSA / SHA256withECDSA)
  → signed asset hashes, protocol constants, identity fields
  → runtime gates 1–10
```

The policy is generated by Gradle from the actual build inputs and signed with
the PKCS12 release key only when local credentials are present. A release build
without credentials produces an unsigned policy that fails closed at runtime.

## 3. Decision logic

`GateEvaluator` is pure Kotlin and unit-tested on the JVM. Fail-closed rules:

- Any `FAIL` makes the whole report fail.
- A release build without a policy fails; it never degrades to "unknown = OK".
- A release build requires all gates to be `PASS`; a `BYPASS` is never a pass.
- Debug builds report signature/pin checks as `BYPASS` and are never reported as
  verified (`passed == false`), but may run for development.
- The failure screen replaces the app surface and offers a re-check.

## 4. Cryptographic inventory

| Primitive | Use | Key |
|-----------|-----|-----|
| APK signature (v2 + v3) | Build authenticity | Official PKCS12 release key (RSA or EC) |
| SHA256withRSA / SHA256withECDSA | Detached policy signature | Same official release key |
| SHA-256 | Asset and certificate fingerprints | None (hash) |
| AES-256-GCM | Existing MAP encryption (`MapCrypto`), unchanged | Existing local map key material |
| HMAC-SHA-256 | **Not used**; no gate needs a symmetric MAC | — |

No private key, password, or key-pack content is embedded in the APK. The build
script verifies that no `.p12`, `.jks`, `.keystore`, `RevCore_Keys.txt`, or
`local-signing.properties` entry is packaged.

## 5. What this does and does not claim

Implemented and source/test verified:

- Identity pinning, policy signature, protected asset hashes, DB schema refusal,
  native-library allow-list, runtime re-verification, core golden vectors, and
  exact asset inventory.
- Interconnected decisions: a failure in any gate prevents ECU communication.

Not claimed:

- Local anti-tamper cannot be made impossible to bypass. A determined attacker
  who patches the DEX and re-signs the APK can remove checks; the official
  certificate pin makes such a build distinguishable, not unbreakable.
- No root, KernelSU, custom-ROM, USB-debugging, or debugger detection is used.
  Those are legitimate environments and are deliberately allowed.
- No hardware verification was performed for this audit (no adapter + ECU
  attached during the build). Gate behaviour is verified by JVM unit tests and
  APK inspection only.
- `assets/dexopt/*` and `integrity_policy.json` are excluded from the inventory
  because AGP generates them and the policy cannot hash itself. Protected asset
  contents are still covered by Gate 3.
